# チラシ向け無料診断導線

## 目的

チラシのQRコードから来た人が、1〜2分で家庭の3日分の備えを確認し、電話または家族によるフォーム申込みを選べるようにする。対象は飯能市・日高市・入間市周辺の家庭であり、高齢者本人とその家族の両方を想定する。

## 画面と導線

1. 既存の3問診断（人数、備蓄、水・食料・トイレ・管理状況）と結果は維持する。
2. 結果の直後に、同じ強さの大きな選択肢を置く。
   - `電話で無料診断する`：`tel:` リンク。公開番号、受付時間、留守番電話へ残す内容を表示する。
   - `家族が代わりに申し込む`：フォームまでスクロールする。
3. フォームの必須項目は「お名前」「地域」「電話番号またはメールアドレス」の3つだけにする。希望日時と相談内容は任意にする。
4. 電話番号もメールアドレスも未入力の場合は、送信前に分かりやすくエラーを出す。プライバシーポリシーへの同意は必須のままにする。

## 表現上の境界

- 無料なのは聞き取り・訪問チェック・見積まで。商品の購入や契約を前提としない。
- 「その場で契約しない」「今ある備えを活かす」を継続表示する。
- 商品価格は診断結果の参考価格であり、正式な見積ではない。
- 電話番号は、ユーザーが明示した公開番号を受け取るまでプレースホルダーにして公開しない。

## アクセシビリティ

- 電話とフォームの主ボタンは、モバイルで少なくとも44 CSS px四方のタップ領域にする。
- 二つの主導線を隣接した小さな文字リンクにはしない。
- フォームのラベル、エラー、必須/任意を視覚とテキストの両方で明確にする。

## 計測と判断

- チラシのQRには `utm_source=flyer`、`utm_medium=print`、`utm_campaign=local_free_check` を付ける。
- `電話する` タップ、診断開始、診断完了、フォーム送信をそれぞれGA4イベントとして記録する。
- 電話対応では「チラシを見た」を確認して電話件数として記録する。
- 最初の100枚について、配布枚数、診断開始・完了、電話、フォーム申込み、予約、成約を同一の表で記録する。閲覧数だけで施策の成否を判断しない。

## テスト

- HTMLテストで電話リンク、フォームの必須/任意、UTM値、主導線の文言を検証する。
- JavaScriptテストで連絡先が両方未入力の場合に送信されないこと、およびイベント名を検証する。
- 既存の全Nodeテストと `git diff --check` を実行する。
