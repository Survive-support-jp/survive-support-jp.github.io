# 飯能 防災備蓄の検索資産設計

## 目的

「飯能 防災備蓄」を調べる家庭に、飯能市の公式情報を起点に、在宅避難が安全な場合の備蓄判断と準備手順を一つのページで完結させる。検索流入は情報記事で受け、相談・販売は地域LPと診断へ分離する。

## 現状

- Search Consoleの直近3か月集計は、通常検索が61表示・5クリック・CTR 8.2%・平均掲載順位10.9。生成AI機能の表示は4回で、最適化の成否を判断できる量ではない。
- `guides/hanno-home-disaster-preparedness.html` は検索に出ているが、5項目の短い概要で、地域LP `bousai/hanno/` と検索意図・説明が重なる。
- 飯能市公式の防災ページは同じ検索結果にあり、自治体の避難情報・公的備蓄を置き換える記事は作らない。

## 方針

### 1. 検索記事を主URLにする

`guides/hanno-home-disaster-preparedness.html` を、以下の意図を満たす実用ガイドに書き直す。

- 飯能市で防災備蓄を始める家庭が、最初に何をどれだけ、どの順番で確認すればよいか。
- 自宅待機が安全な場合と、避難を優先すべき場合を混同しない。
- 水・食料・非常用トイレ・個別配慮品・保管・期限管理を行動単位で確認できる。
- 飯能市の防災ページ、ハザードマップ、地域防災計画を一次情報として案内する。

ページ名は「飯能市の防災備蓄リスト｜家庭で最低3日・できれば1週間分をそろえる順番」とする。本文は語数を目的にせず、この記事だけで準備の開始判断ができる密度にする。自治体の最新避難情報は公式ページを優先することを明記する。

### 2. 地域LPを相談用に限定する

`bousai/hanno/` は「飯能市の防災備蓄・無料チェック」に役割を限定する。主記事の簡易版を繰り返さず、訪問確認の対象、流れ、対応範囲、診断への導線を説明する。検索記事からは、文脈に合う一つのCTAでLPではなく診断へつなぐ。

### 3. 地域×困りごと入口を増やす

既存の地域ガイドを起点に、次の順で別意図のガイドを追加する。

1. 飯能市の非常用トイレ備蓄（既存記事を飯能専用に明確化）
2. 飯能市で高齢者がいる家庭の防災備蓄
3. 停電時のスマホ・情報確保（飯能市を含む地域向けの実用ガイド）

各ページは、同じ本文を都市名だけ置換して量産しない。対象の困りごと、確認手順、一次情報リンク、診断への計測済みCTAを持つ。

## 検索データの運用

Search Consoleの「検索パフォーマンス」で、期間を3か月、検索タイプをウェブに設定し、以下を週1回記録する。

1. クエリとページを確認する。
2. 表示回数があり、平均掲載順位8〜20位の組み合わせを候補とする。
3. そのクエリが示す質問を、該当ページのtitle、H1、冒頭の結論、見出しの順で満たす。
4. 変更日、変更URL、クエリ、表示回数、クリック、CTR、平均順位を記録する。

データ不足の間は、順位やAI表示を成功指標にしない。AI表示は通常検索と別に記録し、十分な表示数が集まるまで原因分析に使わない。

## 独自ドメイン

GitHub Pagesのホスティングは継続可能だが、事業資産としては自前ドメインを取得し、同じGitHub Pagesに接続する。記事改稿とドメイン移転を同時に実施しない。

ドメイン移転時には、旧URLから新URLへの対応表、恒久リダイレクトの動作、canonical、sitemap、Search Consoleでの監視を先に検証する。旧 `github.io` URLが新ドメインへ適切に転送できない場合は、移転を実施しない。

## 検証

- 検索記事には正しいcanonical、Article構造化データ、更新日、飯能市一次情報へのリンクがある。
- 地域LPと検索記事は異なるtitle/H1/役割を持ち、相互に内部リンクする。
- 新規・更新ガイドのCTAに計測属性があり、既存のNodeテストを通る。
- sitemapの更新日とURLが実ページに一致する。
